# Atlas Explorer — Overview-First Redesign (Direction ①)

**Date:** 2026-06-29
**Artifact:** `site/knowledge-work-atlas/` (1,734 tasks · 17 domains · 614 roles)
**Status:** Design approved; ready for implementation plan.

## Goal

Make the Knowledge-Work Atlas genuinely easy and rewarding to *explore* at its current
scale, while keeping it a **single self-contained static file** generated by `build.py`
(no backend, no build toolchain, no external runtime dependencies).

## Problem (grounded in the real data)

The current `index.html` lands the reader on an undifferentiated wall of all 1,734 task
cards. Three concrete problems, each independently confirmed against `tasks.yaml`:

1. **No shape.** Nothing tells the reader where the mass is or where to start.
   Domains are very uneven: Operations & Project Mgmt 299 → Legal 206 → Finance 194 →
   Data/BI 168 → … → Product 50, Strategy 50, Recruiting 44.
2. **Nothing is shareable.** No URL state, so a filtered view ("all the recruiting
   tasks") or a single task cannot be linked or forwarded.
3. **Render jank.** `render()` (`build.py:199`) builds DOM for *all* matching cards on
   every keystroke; the generated file is ~1.1 MB.

Plus the **role control is broken**: a single `<select>` with 614 options (79 of which
point at exactly one task; 549 have ≤5). It is the worst single usability bug on the page.

Supporting facts used by this design:
- automation: medium 1091 · **high 546** · low 97 → 546 high-automation tasks are a
  natural "quick wins" entry point.
- `human_in_loop`: review-before-send 868 · spot-check 469 · approve 288 · sign-off 93 ·
  none 16 → a 100%-unused field that cleanly answers "can this run unattended?".
- `tools` is the only dirty field: 438 raw strings collapse to 398 across 40 casing-dupe
  groups; biggest is `spreadsheet` 857 + `Spreadsheet` 214 = **1,071** (the single most
  common entry point in the catalog). Normalizing it fixes search matching.

## Decision

Front door is organized around **domain** ("browse the map"), not role. Role remains a
first-class *filter* (now a type-ahead), but is deliberately not a landing primitive
because of the 614-item long tail. This is Direction ① from the ideation pass; the
role-centric "Automation Report" (Direction ②) and a full faceted panel (Direction ③)
are explicitly deferred.

## Architecture — three hash-routed levels, one file

```
Home (#)                      Domain (#d=<Domain>[&role=&auto=&q=])      Task (#t=<id>)
17 domain tiles, count-sorted  drill-in: breadcrumb + scoped filters     existing modal,
+ pinned search                + grouped/windowed results                now addressable
+ "⚡ Quick wins (546)" chip
+ "Browse everything" link
```

### Level 0 — Home (new default)
- Grid of **17 domain tiles**, sorted by task count descending.
- Each tile shows: domain name · big task count · a thin **high/med/low automation
  mini-bar** (reuse existing `--a-high / --a-med / --a-low` colors) · top 2–3 roles.
- Pinned **search box** at the top (escape hatch; a query jumps straight to cross-domain
  results).
- **"⚡ Quick wins (546)"** chip → sets `auto=high` across all domains.
- **"Browse everything"** link → today's flat grid, unscoped.
- Renders ~17 tiles instead of 1,734 cards → instant, and doubles as the perf fix for the
  default view.

### Level 1 — Domain view
- Breadcrumb (`Overview / <Domain>`) + domain header + task count + **"Copy link"** button.
- Role + automation filters **scoped to the selected domain**, each option label carrying
  a **facet count**, e.g. `Recruiter (12)`, `High (96)`.
- Role filter becomes a **type-ahead** via a native `<input list=...>` + `<datalist>`
  (dependency-free), replacing the 614-option `<select>`.
- Results render windowed (see below).

### Cross-domain results (search with no domain selected)
- Render **sticky domain group-headers** with per-group counts
  (`Finance & Accounting — 12`) instead of a flat grid. Data is already domain-sorted at
  `build.py:81`, so this is primarily a render change.

### Level 2 — Task
- The existing modal (`openModal`, `build.py:217`), now addressable by `#t=<id>`: opening
  a task writes `#t=`, closing clears it, and loading the page on a `#t=` URL opens that
  task directly.

## URL scheme (hash-based)

Static hosting on Cloudflare Pages has no server rewrites, so state lives in the **hash**,
not the path or querystring:

- `#`               → Home
- `#d=Recruiting%20%26%20Talent`                     → domain view
- `#d=…&role=Recruiter&auto=high&q=screening`        → full filter state
- `#t=<task-id>`                                     → a single task

Routing rules:
- `pushState` on navigation jumps (tile click, open task) → Back/Forward work.
- `replaceState` while typing in search → history is not polluted per keystroke.
- a `popstate` / `hashchange` listener re-renders state from the hash → Back/Forward are free.

## Rendering — windowed

Replace eager rendering with a window:
- Paint the first ~60 matching cards.
- Append more via a bottom **IntersectionObserver sentinel** as the reader scrolls.
- **Reset the window** on every filter/search/route change (correctness-critical).

## Changes to `build.py`

**Python (data/precompute, near `build.py:83–91`):**
- Precompute **per-domain meta** — `{count, high, medium, low, topRoles}` — and embed it in
  `META_JSON` so tiles render without recomputation in JS.
- **Normalize `tools`**: lowercase + strip to one canonical label and **write it back onto
  each record** so search matching and any future facet agree (438 → 398 distinct; collapses
  all 40 dupe groups; `spreadsheet` becomes a single 1,071-task term). ~5 lines, no UI.
- Append per-option facet counts where needed (domain/role/automation).

**Template + embedded JS (`build.py:93–236`):**
- Add Home overview container (domain-tile grid) + breadcrumb/domain-header bar + group-header
  markup; hide the flat grid by default.
- Add a tiny **hash router** (parse hash → state on load; write hash on filter/nav change;
  `popstate`/`hashchange` → re-render).
- Split `render()` (`build.py:199`) into `renderHome()`, `renderDomain()`, and a grouped
  `renderResults()` that emits sticky domain headers with counts.
- Implement **windowing** (first ~60 + IntersectionObserver, reset on change).
- Update `openModal` to set/clear `#t=` and to open the matching task on load.
- Replace the role `<select>` (markup `build.py:165`, populated at `build.py:188`) with a
  type-ahead `<input>`+`<datalist>`.
- Append facet counts to option labels.

**README.md:** regenerated by the same `build.py` run; update the "Explore" section copy to
describe the overview/drill-down/shareable-link model.

## Scope

**In scope**
- Home → Domain → Task hash-routed IA.
- Shareable hash URLs + Back/Forward.
- Windowed rendering.
- Domain tiles with counts + automation mini-bars.
- Sticky domain group-headers in cross-domain results.
- Type-ahead role filter (`<datalist>`).
- Facet counts on filter options.
- "⚡ Quick wins (546)" entry.
- `tools` normalization in `build.py` (data hygiene; unlocks search; no UI on its own).
- Near-free per-card **"runs unattended" vs "keep a human"** badge derived from
  `human_in_loop` (none/spot-check → unattended; approve/sign-off → keep a human;
  review-before-send → keep a human).

**Deferred (revisit after this ships)**
- Direction ② — role type-ahead *landing* → ranked personal "Automation Report" + copy-able
  markdown shortlist.
- Direction ③ — full multi-select faceted panel; `frequency` + `human_in_loop` as
  filterable facets (the per-card badge above is the cheap slice we take now); preset
  "lens" chips beyond Quick wins.

## Testing / verification

`build.py` is dependency-free; verification is manual + a build smoke check:
- `python3 build.py` runs clean and reports the same task/domain/role counts as today
  (1734 / 17 / 614) — i.e. normalization and precompute did not drop or duplicate records.
- Tile counts sum to 1,734; per-domain mini-bar high/med/low sum to each tile's count.
- Hash round-trips: load `#d=…&role=…&auto=…&q=…` reproduces the exact view; copy-link
  yields a URL that reloads to the same state; `#t=<id>` opens the right task; Back/Forward
  step through navigation; typing does not spam history.
- Windowing: large domains (Operations 299) and a broad search paint quickly, then load on
  scroll; switching filters resets the window (no stale/duplicated cards).
- Type-ahead resolves a known role and scopes results; clearing it restores the domain.
- Open `index.html` directly from disk (file://) — still works with no server.

## Risks & mitigations

- **One extra click before tasks.** Mitigate with the always-visible pinned search and the
  "Browse everything" link so nothing is gated behind the overview.
- **Hash URLs are less pretty than clean paths** — but the only robust option for a static
  file with no server rewrites.
- **More moving parts than today's dead-simple render** (router + windowing + tiles). Keep
  each piece small and give the windowed renderer a focused correctness pass (window reset
  on every state change).
- **Normalization writes back onto records** — must run before search/anything consuming
  tools, and must not change task identity or counts (verified in the smoke check).
- **`human_in_loop` → badge mapping is an editorial call.** Keep the mapping explicit and
  visible; it is a hint, not a guarantee.
